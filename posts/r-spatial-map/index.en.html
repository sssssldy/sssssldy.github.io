📌 1. Introduction and Environment Configuration

This tutorial demonstrates how to leverage the latest sf (vector) and terra (raster) ecosystem in R to automatically match specific urban administrative boundaries with large-scale remote sensing TIF imagery. Combined with lake sampling point data, we will render publication-quality macro city overviews and localized detailed inset maps.

🌟 Core Highlights

  • Full Automation & Intelligence: Simply modify a single city code switch (e.g., JN), and the subsequent administrative boundary extraction and TIF tile matching will execute fully automatically.
  • Overlap-Free Coordinate Axes: By dynamically computing breaks, this workflow thoroughly resolves the common pain point of overlapping longitude/latitude labels when using coord_sf at zoomed-in local scales.
  • Robust Fault Tolerance: Features a built-in diagnostic and correction logic to handle coordinate flipping (reversed latitude/longitude) often found in open-source spatial datasets.

🧹 3. Data Cleaning and Factor Order Locking

To ensure academic compliance and standard formatting of the map legend (e.g., sorting urbanization intensity from high to low: H -> M -> L), we need to factorize the unstructured attribute data and project all vectors into the globally standard WGS84 geographic coordinate system (EPSG:4326).

# Uniformly transform to WGS84 geographic coordinate system
china_map_4326 <- st_transform(china_map, crs = 4326)

# Dynamically filter and explicitly lock the legend display order: city_H -> city_M -> city_L
df_current <- lake_data %>% 
  filter(City_Name == target_city) %>% 
  mutate(City_Group = factor(City_Group, levels = c("city_H", "city_M", "city_L")))

# Convert to an sf spatial vector object
df_current_sf <- st_as_sf(df_current, coords = c("Centroid_X", "Centroid_Y"), crs = 4326)

🤖 4. Automated Boundary Synthesis and Coordinate Inversion Diagnosis

When dealing with shapefiles from unverified open sources, one frequently encounters inverted coordinates (swapped X/Y coordinates), causing the rendered map to shift unexpectedly to the Arctic or Antarctic. This segment implements an automated blind check and correction routine.

# Automatically find and merge the complete administrative contour for the current city
current_boundary <- china_map_4326[st_intersects(china_map_4326, df_current_sf, sparse = FALSE) %>% rowSums() > 0, ] %>% 
  st_union()

# Automatically diagnose if the current city's shapefile boundary suffers from coordinate inversion
bbox_check <- st_bbox(current_boundary)
if (mean(c(bbox_check[["xmin"]], bbox_check[["xmax"]])) < mean(c(bbox_check[["ymin"]], bbox_check[["ymax"]]))) {
  cat("⚠️ Warning: Detected coordinate inversion in the administrative shp file. Automatically correcting...\n")
  current_boundary <- st_flip_coordinates(current_boundary)
}

# Ensure conversion to a standard terra vector object
city_vector_4326 <- vect(current_boundary)

🔍 5. Intelligent Cropping and Validity Matching for Large-Scale Raster TIFs

When dealing with massive, tiled remote sensing TIF images (such as urbanization weight data), blindly merging them is highly memory-intensive.

The logic of this algorithm is: first perform a blind check on whether the geometric bounding boxes intersect ➡️ execute a spatial trial clip ➡️ calculate whether there are non-NA valid pixels within the clipped region. A TIF tile will only be loaded if it actually contributes valid data to the target area.

tif_files   <- list.files(tif_dir, pattern = "\\.tif$", full.names = TRUE)
raster_list <- lapply(tif_files, rast)

selected_raster_4326 <- NULL

for (i in seq_along(raster_list)) {
  r <- raster_list[[i]]
  r_4326 <- project(r, "EPSG:4326", method = "near")
  
  # Step A: Bounding box intersection check
  is_intersected <- is.related(ext(r_4326), city_vector_4326, "intersects")
  
  if (is_intersected) {
    # Step B: Trial crop and check for null values
    test_crop <- crop(r_4326, city_vector_4326)
    valid_pixels <- sum(!is.na(values(test_crop)))
    
    if (valid_pixels > 0) {
      selected_raster_4326 <- r_4326
      cat(paste0("📊 Smart match successful! ", target_city, " found ", valid_pixels, " valid urbanization pixels in TIF #", i, ".\n"))
      break
    } else {
      cat(paste0("ℹ️ Notice: TIF #", i, " intersects geometrically but contains only NA values within the ", target_city, " boundary. Skipping...\n"))
    }
  }
}

📐 6. Dynamic Range Calculation and Safe Spatial Cropping

To generate two distinct perspectives—the macro overview map and the local detailed map—we need to dynamically calculate their respective bounding boxes and add an appropriate buffer margin (padding) to prevent edge clipping.

# 1. Dynamically calculate the bounding box for the local inset map
bbox_points <- st_bbox(df_current_sf)
x_point_padding <- (bbox_points[["xmax"]] - bbox_points[["xmin"]]) * 0.1
y_point_padding <- (bbox_points[["ymax"]] - bbox_points[["ymin"]]) * 0.1

local_xlim <- c(bbox_points[["xmin"]] - x_point_padding, bbox_points[["xmax"]] + x_point_padding)
local_ylim <- c(bbox_points[["ymin"]] - y_point_padding, bbox_points[["ymax"]] + y_point_padding)
local_extent_4326 <- ext(local_xlim[1], local_xlim[2], local_ylim[1], local_ylim[2])

# 2. Dynamically calculate the bounding box for the macro city overview map
bbox_city <- st_bbox(current_boundary)
x_city_padding <- (bbox_city[["xmax"]] - bbox_city[["xmin"]]) * 0.05
y_city_padding <- (bbox_city[["ymax"]] - bbox_city[["ymin"]]) * 0.05
